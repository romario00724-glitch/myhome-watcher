# myhome-watcher

Бот стежить за пошуком на myhome.ge (оренда квартир у Батумі, лише власники) і шле **нові**
оголошення в робочу Telegram-групу «Скрапер Myhome.Ge (власники)». Під кожним оголошенням —
кнопка «📢 Додати в канал»: вона публікує оголошення в канал `@arendabatumi3`
(«Аренда Батуми 🏢 Batumi Rent») у його стилі. Уся логіка — в одному файлі `watcher.py`.
Мова коду, коментарів і повідомлень — українська; пости в каналі — російською.

## Як запускається

```
cron-job.org ──► workflow_dispatch ──► GitHub Actions: python watcher.py --once --listen 600
 кожні 10 хв                            1) натискання кнопок, що вже чекають
                                        2) один прохід по myhome.ge (нові оголошення → група)
                                        3) слухає кнопки до ~25 с перед наступним 10-хв слотом
```

- **Будильник — cron-job.org** (job `myhome-watcher`), а не `schedule:` у `watch.yml`: розклад
  GitHub у цьому репо спрацьовував ~раз на 2,5 год. `cron:` лишився як запасний. Будильник
  ходить у GitHub API fine-grained токеном (`Actions: Read and write`, лише цей репо), що
  **спливає 28.09.2027** — тоді бот тихо замовкне, прийде лист від cron-job.org. Деталі й
  коди помилок — README, розділ «Хто насправді запускає бота».
- **На myhome.ge бот ходить раз на запуск** (раз на 10 хв). Під час прослуховування — лише
  Telegram long polling. Додаткові запити до сайту — тільки на натискання кнопки (картка + фото).
- Запуски йдуть строго по одному (`concurrency`), кожен сам завершується перед наступним.
  Checkout бере `ref: ${{ github.ref_name }}`, щоб запуск із черги не працював зі старим
  `state.json`.
- Після запуску workflow комітить `state.json` у `main` (`state: update [skip ci]`) — тому
  локальний `main` постійно відстає: перед роботою `git pull`.

## Секрети й налаштування

GitHub → Settings → Secrets and variables → Actions:

| Назва | Що це |
|---|---|
| `TELEGRAM_BOT_TOKEN` (secret) | токен бота; **перевипущений 29.09.2026** (див. нижче) |
| `TELEGRAM_CHAT_ID` (secret) | робоча група, куди йдуть оголошення |
| `TELEGRAM_CHANNEL_ID` (secret) | `@arendabatumi3`; приймає й `https://t.me/...` або `-100...`. Без нього кнопки немає |
| `OPENAI_API_KEY` (secret) | текст поста для каналу й переклад грузинських/англійських описів |
| `OPENAI_MODEL` (variable) | необов'язкова; за замовчуванням `gpt-5-mini` |

Локально — `telegram.json` у корені (`token`, `chat_id`, `channel_id`, `openai_key`), у
`.gitignore`. Репозиторій **публічний**: жодних ключів у коді й комітах.

## Кнопка «Додати в канал» — що вирішили

- Натискання → `handle_callback`: кнопка одразу стає «⏳ Публікую…» → `post_to_channel`
  бере свіжу картку з myhome.ge, альбом до 10 фото, підпис за `channel_template.txt` →
  кнопка «✅ В каналі» з посиланням. Помилка → кнопка повертається, пояснення в чат.
- **Повторів немає**: опубліковане пишеться в `state["posted"]` за id оголошення, хоч
  хто і скільки разів тисне.
- Картка оголошення не завжди віддає кімнати/спальні/район, тому їх запам'ятовуємо з видачі
  пошуку при надсиланні в групу (`state["facts"]`, `remember_facts`).
- Текст: заголовок з відмінком району, пункти «✔️ Срок / Состояние…», умови оплати й адресу
  пише OpenAI (`AI_PROMPT`); без ключа або при збої — звичайний шаблон + попередження в чат.
  Контакт у шаблоні — завжди `+995595102906 — Ольга`. Телефони власника з опису прибираються.
- **Чому бот «слухає» між перевірками.** 29.09.2026 натискання губилися: Telegram тримає
  callback недовго, і бот, що прокидається раз на 10 хв, їх не заставав (у ручних запусках
  одразу після натискання все працювало). Спершу грішили на сторонню програму з тим самим
  токеном і **перевипустили токен** — не допомогло, але й не зашкодило. Справжній фікс —
  `--listen`. Cloudflare Worker / вебхук / VPS розглядали й відкинули як зайве.
- Побічний ефект нового токена: він же ключ HMAC для відбитків телефонів у `state.json`
  (`phone_fingerprint`), тож лічильник «телефон уже траплявся» почав рахувати заново.

## Правила роботи з кодом

- **Не запускати `python watcher.py` на комп'ютері паралельно з GitHub** — дві копії
  відбирають натискання одна в одної.
- **`import watcher` + наявний `telegram.json` = реальні повідомлення** в робочу групу й
  канал. У тестах глушити `tg_call`, `fetch_listing`, `_post_json` (OpenAI), `save_state`.
  Токен у локальному `telegram.json` може бути старим, відкликаним — тоді він просто не працює.
- Діагностика кнопок у логах Actions: `кнопки: отримано оновлень…`, `кнопка … пропущена`,
  `Telegram нічого не віддав; webhook=…`. Лічильник прочитаних натискань — `state["tg_offset"]`.
- Перевірка шаблону без публікації: `python watcher.py --preview <id>`; вручну в канал:
  `python watcher.py --post <id>`.
- Користувач не програміст: пояснювати простими словами, українською.
