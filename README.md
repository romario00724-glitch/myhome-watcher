# Монітор myhome.ge → Telegram

Кожні ~10 хвилин перевіряє пошук на myhome.ge (лише оголошення від власників) і надсилає в Telegram тільки **нові** оголошення: фото, ціна, район, телефон (якщо є), посилання. Агентів, які прикидаються власниками, позначає ⚠️.

Файли: `watcher.py` — скрипт, `searches.txt` — посилання на пошук, `requirements.txt` — залежності, `.github/workflows/watch.yml` — автозапуск на GitHub.

---

## 1. Telegram-бот (5 хвилин)

1. У Telegram відкрийте **@BotFather** → `/newbot` → придумайте назву. Він дасть **токен** виду `7123456789:AAH...`.
2. Той, хто отримуватиме оголошення, відкриває свого бота й тисне **Start**.
   Хочете отримувати обоє — створіть групу й додайте туди бота.
3. Дізнайтеся **chat_id**: відкрийте в браузері
   `https://api.telegram.org/bot<ТОКЕН>/getUpdates` і знайдіть `"chat":{"id":123456789`.
   (Або `python watcher.py --chat-id`, коли токен уже вказаний.) У групи id від'ємний, з мінусом.
   Кілька чатів — через кому: `123456789,-100987654321`.

## 2. Посилання з myhome.ge

1. На myhome.ge оберіть: **Аренда** (або **Продажа**) → **Квартира** → **Батуми**, за бажанням район, ціну, кімнати, і увімкніть **Собственник**.
2. Натисніть «Поиск» і скопіюйте адресу з адресного рядка. У ній мають бути `deal_types=` і `cities=`.
3. Вставте в `searches.txt` замість `ВСТАВТЕ_СЮДИ_ПОСИЛАННЯ`. Можна кілька рядків, наприклад оренда й продаж окремо:
   ```
   Оренда | https://www.myhome.ge/...?deal_types=2&...&cities=...
   Продаж | https://www.myhome.ge/...?deal_types=1&...&cities=...
   ```

Фільтр «Власник» скрипт додає сам. Новий рядок у `searches.txt` при першому запуску тихо «запам'ятовує» поточні оголошення, щоб не засипати чат старими.

## 3а. Перевірка на своєму комп'ютері

Потрібен Python 3.10+ (python.org). У папці з файлами:

```
pip install -r requirements.txt
```

Токен і chat_id або впишіть угорі `watcher.py`, або задайте в терміналі:

- Mac/Linux: `export TELEGRAM_BOT_TOKEN="..."` і `export TELEGRAM_CHAT_ID="..."`
- Windows (PowerShell): `$env:TELEGRAM_BOT_TOKEN="..."` і `$env:TELEGRAM_CHAT_ID="..."`

Далі:

```
python watcher.py --test    # покаже 3 свіжі оголошення і надішле 1 тестове в Telegram
python watcher.py           # стежить, поки комп'ютер увімкнений (Ctrl+C — зупинити)
```

У `--test` перевірте два рядки:
- «міста: …» — там має бути Батумі;
- «Кількість оголошень автора на сайті: N (поле …) ✅». Якщо замість цього написано «не знайдено», запустіть `python watcher.py --dump` і надішліть файли `dump_list.json` і `dump_detail.json` — по них видно, як сайт називає це поле.

## 3б. Цілодобово й безкоштовно на GitHub

1. github.com → **New repository** → **Public** → Create.
2. «uploading an existing file» → перетягніть `watcher.py`, `searches.txt`, `requirements.txt`, `README.md` → **Commit**.
3. **Add file → Create new file**, назва: `.github/workflows/watch.yml`, вставте вміст однойменного файлу → **Commit**.
4. **Settings → Secrets and variables → Actions → New repository secret**: додайте `TELEGRAM_BOT_TOKEN` і `TELEGRAM_CHAT_ID`.
5. **Actions → myhome-watcher → Run workflow**. Перший запуск надішле «✅ Стежу за пошуком…», далі нові оголошення приходитимуть самі.

Нотатки:
- У публічному репозиторії запуски безкоштовні без обмежень. Видно в ньому лише код, посилання на пошук і `state.json` (номери вже побачених оголошень); токен захований у Secrets.
- Приватний репозиторій теж можна, але там 2000 безкоштовних хвилин на місяць — поставте у `watch.yml` інтервал `*/30 * * * *`.
- Розклад GitHub (`cron:`) на практиці пропускає майже всі слоти — тому запускає бота зовнішній будильник, див. розділ «Хто насправді запускає бота» нижче.
- Змінити пошук можна прямо на сайті GitHub: відкрийте `searches.txt` → олівець → збережіть.

## Переклад грузинських і англійських оголошень

Якщо додати секрет `OPENAI_API_KEY` (ключ з platform.openai.com → API keys), бот перекладає
російською опис і адресу оголошень, написаних грузинською чи англійською. Російськомовні
не чіпає — на них ШІ не викликається зовсім. Без ключа все працює, просто без перекладу.

- Локально ключ — `"openai_key": "sk-..."` у `telegram.json`.
- Модель за замовчуванням — `gpt-5-mini` (частки цента за оголошення). Іншу можна вказати в
  **Settings → Secrets and variables → Actions → Variables** змінною `OPENAI_MODEL`.
- Вимкнути — `TRANSLATE_ALERTS = False` угорі `watcher.py`.

## Хто насправді запускає бота

У `watch.yml` є розклад GitHub (`cron:`), але **покладатися на нього не вийшло**. Замір за
перші 8 годин роботи: замість ~48 перевірок відбулося **2** — фактичний інтервал ~2,5 години
замість 10 хвилин. GitHub пропускає майже всі заплановані слоти безплатних публічних
репозиторіїв, і зсув із круглих хвилин цього не вилікував. Нічого при цьому не губиться
(бот звіряється зі своєю базою, а не з годинником), але дізнаватися про хорошу квартиру
через 2,5 години — це часто дізнаватися останнім.

Тому справжній будильник — зовнішній і безплатний **cron-job.org**. Він щодесять хвилин
сам натискає «Run workflow» через GitHub API:

```
cron-job.org ──► GitHub Actions ──► myhome.ge ──► Telegram
 кожні 10 хв       ~25 секунд        читає      картка в групу
```

Ознака, що все саме так: в **Actions** у кожного запуску написано `workflow_dispatch`,
а не `schedule`. Розклад у `watch.yml` лишили як запасний — якщо cron-job.org колись ляже,
бот усе одно перевірятиме сайт, хай і рідко. Одночасно вони не заважають: у workflow
стоїть `concurrency`.

### Як налаштований будильник

Завдання `myhome-watcher` на [console.cron-job.org](https://console.cron-job.org/jobs):

| Поле | Значення |
|---|---|
| URL | `https://api.github.com/repos/romario00724-glitch/myhome-watcher/actions/workflows/watch.yml/dispatches` |
| Розклад | Every 10 minutes (`*/10 * * * *`) |
| Request method | `POST` |
| Request body | `{"ref":"main"}` |
| Заголовок `Accept` | `application/vnd.github+json` |
| Заголовок `Authorization` | `Bearer github_pat_…` — ключ доступу GitHub |
| Заголовок `X-GitHub-Api-Version` | `2022-11-28` |

Ключ — це **fine-grained token** GitHub з єдиним правом `Actions: Read and write` на цей
репозиторій (плюс обов'язковий `Metadata: Read-only`). Ні коду, ні інших репозиторіїв він
не відкриває. Відкликати: [github.com/settings/personal-access-tokens](https://github.com/settings/personal-access-tokens).

У блоці «Notify me when…» увімкнено сповіщення на пошту: про збій (після **2** невдач
поспіль), про відновлення після збою і про вимкнення завдання через надто багато помилок.

### ⚠️ 28 вересня 2027 — спливає ключ

Токен виданий на рік. Коли він спливе, cron-job.org почне отримувати від GitHub `401`,
перестане запускати перевірки — і бот замовкне. **У Telegram при цьому не буде жодної
помилки, просто тиша**, а тиша там і так буває по кілька годин. Саме для цього й увімкнені
сповіщення: прийде лист.

Лікується за дві хвилини:
[github.com/settings/personal-access-tokens/new](https://github.com/settings/personal-access-tokens/new)
→ новий токен, `Only select repositories` → `myhome-watcher`, право `Actions: Read and write`
→ підставити його в заголовок `Authorization` того самого завдання на cron-job.org → **SAVE**.

### Як перевірити, що бот живий

Відкрити [Actions репозиторію](https://github.com/romario00724-glitch/myhome-watcher/actions):
якщо верхній запуск свіжий (не старший за ~15 хвилин) і зелений — усе гаразд.
`нових оголошень немає` у логу — нормальна відповідь, а не поломка: бот сходив на сайт,
звірив із базою й не знайшов нічого нового.

Коди помилок від будильника (видно в cron-job.org, кнопка **TEST RUN** унизу сторінки EDIT):
`204` — усе правильно; `401` — ключ сплив або скопійовано не повністю (чи забуте слово
`Bearer ` перед ним); `404` — ключу не дали доступ до репозиторію або не поставлено
`Actions: Read and write`; `422` — не вставлено тіло `{"ref":"main"}`.

## Що означають позначки

- **Плашка «Агент» на сайті.** Якщо в картці оголошення myhome.ge сам позначив автора як агента, бот таке оголошення не надсилає (у журналі запуску — «пропускаю …: на сайті автор позначений як «agent»»). Буває, що видача «лише власники» ще показує такого автора як власника, а картка вже каже «Агент» — бот вірить картці. З `SKIP_SITE_AGENTS = False` такі оголошення приходять з позначкою **⚠️ На myhome.ge автор позначений як агент**.
- **✅ У автора 1 оголошення на myhome.ge** / **⚠️ У автора 25 оголошень на myhome.ge** — скільки оголошень у цього автора на всьому сайті (береться з картки оголошення, працює з першого дня). З `AGENT_THRESHOLD` і більше — це агент під виглядом власника або інвестор із кількома квартирами (теж цікавий контакт).
- **⚠️ Цей автор або телефон уже трапився в N оголошеннях** — власна база скрипта. З'являється, коли вона знає більше за сайт (наприклад, той самий телефон на кількох акаунтах) або коли сайт лічильник не віддав.
- **⚠️ В описі згадується агенція або комісія.**
- **✍️ Пише, що без посередників** — лише підказка, агенти теж так пишуть.

Телефон на myhome.ge часто прихований (`599404***`). Якщо власник вписав номер в опис, скрипт покаже його повністю.

## Налаштування (вгорі `watcher.py`)

- `AGENT_THRESHOLD = 3` — з якої кількості оголошень автора ставити ⚠️.
- `SKIP_SUSPECTED_AGENTS = False` — `True`, щоб таких узагалі не надсилати (рахується більше з двох чисел: на сайті чи в базі скрипта).
- `SKIP_SITE_AGENTS = True` — не надсилати оголошення, де сайт сам поставив плашку «Агент»; `False` — надсилати з ⚠️.
- `LANG = "ru"` — мова назв і посилань (`ru` / `en` / `ka`).
- `MAX_ALERTS_PER_RUN = 25` — максимум повідомлень за одну перевірку.

## Якщо щось не так

- **HTTP 403 / «відповідь не JSON»** — myhome.ge прийняв запит за бота. Перевірте, що встановлено `curl_cffi`. Якщо на GitHub це повторюється годину поспіль, бот сам напише в Telegram.
- **«немає фільтра міста»** — у посиланні немає `cities=`. Застосуйте фільтри на сайті ще раз і скопіюйте адресу.
- **У Actions помилка push (403)** — Settings → Actions → General → Workflow permissions → **Read and write**.
- **Почати з нуля** — `python watcher.py --reset` (або видаліть `state.json` на GitHub).
- Скрипт працює через внутрішній API сайту. Якщо myhome.ge його змінить, скрипт доведеться підправити.
